# 设计方案

## 世界地图

- 地图覆盖全球，使用球面模型。
- 现实地图只约束自然地理；城市、省份、人口、经济与政治均由游戏过程产生。
- 自然地理包括地形、气候、水文、生物群落、自然资源和矿藏。
- 时间跨度覆盖数千年的人类文明发展。

## 地理空间架构

地形和逻辑网格是两套职责不同、彼此独立的系统：

- 地形系统负责球体表面形状、细节层级和地形渲染。
- 逻辑网格负责地块身份、邻接关系以及以地块为单位的玩法状态和操作。
- 地形 `Chunk` 不保存地块身份，逻辑地块也不依赖某个地形 `Chunk`。镜头引起的地形 LOD 变化不会改变地块语义。
- 两套系统只在查询和显示边界相交：例如根据空间位置选择地块，或在地形表面显示地块边界与选中状态。

### 地形系统

地形系统目前已经基本实现，仍存在的局部问题不改变以下架构：

- 球体由六个立方体面构成。每个面的规则顶点使用等角 Cube-sphere 映射投影到球面，以减小面内尺度差异。
- 每个面使用四叉树组织 `Chunk`。运行时根据视锥、地平线遮挡和屏幕空间几何误差选择当前需要的 LOD。
- 地形由离线生成的静态资产定义。资产保存构建参数、最高精度参考高程和各级 `Chunk` 的包围范围、几何误差等派生元数据，并带有格式版本和完整性校验。
- 运行时读取资产中的高程、细分参数和 `Chunk` 元数据，再为当前可见 LOD 按需构造并缓存渲染网格；资产不保存每一级现成的 GPU Mesh。
- `ChunkResolution`、`MaximumLod` 和最大高程尺度属于资产构建配方，不是设计不变量。运行时以资产内记录的值为准，设计文档不固定其具体数值。

### 逻辑网格与地块显示

逻辑网格是接下来准备实施的部分。已经确定的方向如下：

- 网格使用固定频率为 `358` 的细分二十面体及其球面 Voronoi 对偶，共有 `1,281,642` 个地块，其中 12 个是五边形，其余是六边形。
- 逻辑网格不创建一套与地形平行、覆盖全球且长期存在的渲染 Mesh。逻辑拓扑采用何种预生成或运行时计算方案仍待实现阶段确定。
- Tile 选择以数学空间查询完成，不依赖一套用于拾取的平行网格 Mesh。具体查询结构和是否使用预生成辅助数据仍待确定。
- 地块显示只生成当前需要的局部视觉结果。当前优先考虑在可见地形 `Chunk` 上通过 Shader 表达边界、填充或选中效果，但该实现尚未定案，不作为架构不变量。

## 地块

- 地块是最小的地理、状态和操作单元。
- 球面由频率为 `358` 的细分二十面体对偶网格覆盖，绝大多数地块为六边形，并包含球面拓扑必需的 12 个五边形。
- 每个地块平均面积约为 **400 km²**；五边形在规则上视为与六边形等面积。
- 全球约有 128 万个地块，其中陆地地块约 38 万个。
- 地块具有固定标识和邻接关系；移动、战争和领土操作均以地块为边界。
- 道路是相邻地块之间的连接。
- 陆地地块采用统一的数据结构，不设置特殊的“空地块”类型。

## 自然地理

本节记录自然地块属性与机制。采集强度、劳动力、技术、设施和资源发现等人文机制不在本节范围内。

- 气候和生物群落模板在第一版中固定，不模拟长期气候迁移、生态演替或物种灭绝。
- 所有分类均由数据模板定义。模板使用稳定字符串键持久化，加载后映射为紧凑数字 ID。

### 地形与土地使用

所有地块使用同一个地形分类：

```text
Plain / Hills / Mountains / ShallowWater / DeepWater
```

- 陆地类型表达地表起伏，水域类型表达深度。
- 海洋和湖泊身份由独立水体对象表达；沿海由陆地与水域邻接推导。
- 地形模板提供可开发面积比例。
- 农田与建设用地共享可开发面积上限；道路、矿山等小型设施第一版不计占地。

```text
农田覆盖率 + 建设用地覆盖率 ≤ 地形可开发面积比例 ≤ 1
```

```text
自然覆盖率 = 1 - 农田覆盖率 - 建设用地覆盖率
```

- 自然覆盖率是派生值，不单独保存。
- 不设置“恢复中的裸露土地”或自然覆盖恢复机制。
- 农田中没有种植作物的部分是休耕地，仍属于农田，不计入自然覆盖。
- 停种只形成休耕；明确弃耕才减少农田覆盖率。
- 弃耕或废弃建设用地会立即扩大自然资源的环境容量，但资源数量仍需通过繁衍恢复。

### 气候与丰容度

每个地块引用一个固定的气候模板。气候模板至少提供：

```text
ClimateTemplate
- baseMaximumRichness
- richnessRecoveryRate
- monthlyMovementFactors[12]
- monthlyMilitaryFactors[12]
```

- 丰容度是非负的抽象环境容量值，不归一化到 `0～1`，也不设置统一数值上限。
- 气候提供基础最大丰容度和丰容恢复率。
- 水系与湖泊提高相邻陆地地块的最大丰容度。
- 南北半球可以通过月份偏移复用气候模板的军事和移动季节系数。
- 农作物与自然资源的产出均采用月度平均值，不设置各自的月度产出周期。

```text
最大丰容度 = max(
    0,
    气候基础最大丰容度
  + Σ 去重后的水系修正
  + Σ 去重后的湖泊修正
)
```

```text
0 ≤ 当前丰容度 ≤ 最大丰容度
```

```text
丰容自然恢复 =
    气候丰容恢复率
  × (最大丰容度 - 当前丰容度)
```

丰容恢复随缺口缩小而逐渐减慢。自然资源种群的繁衍使用另一套指数增长机制，不使用丰容缺口公式。

### 生物群落与适应系数

陆地和水域地块共用同一套生物群落机制，只承载不同模板数据。

```text
BiomeTemplate
- naturalResources[]
- suitableCrops[]
```

```text
BiomeNaturalResourceEntry
- resourceId
- adaptationCoefficient
```

```text
BiomeCropEntry
- cropId
- adaptationCoefficient
```

- 自然资源条目表示游戏级资源种群，例如木材植被、野味动物、药用植物和渔业生物，不表示真实生物学物种。
- 适应系数表示该资源种群或作物在当地的生长活跃程度。
- 适应系数参与环境容量；对于自然资源，还参与繁衍速度。
- 水域生物群落可以拥有渔业等自然资源，适宜作物列表第一版为空。
- 群落中不存在的作物，其自然适应系数视为零。未来技术或设施可以覆盖该自然限制。

### 自然资源种群

自然资源模板提供资源自身的通用参数：

```text
NaturalResourceTemplate
- unitOutput
- baseReproductionRate
```

地块只为所属生物群落列出的自然资源保存当前数量。

```text
自然资源最大容量 =
    当前丰容度
  × 自然覆盖率
  × 当地适应系数
```

所有自然资源共享一个全局固定的最低繁衍基数：

```text
实际最低数量 = min(
    全局最低繁衍基数,
    自然资源最大容量
)
```

```text
实际最低数量 ≤ 当前数量 ≤ 自然资源最大容量
```

- 最低繁衍基数是当前数量的有效下限，不另设隐藏状态或零丰度状态。
- 最低繁衍基数不可采集，也不产生资源产出。
- 环境容量降至低于最低基数时，实际最低数量随容量降低；容量为零时数量才为零。
- 环境容量恢复到高于固定基数时，当前数量自动提升到固定基数，用来抽象残存种群、种子和邻近迁入。
- 环境容量下降时，超过新上限的数量立即裁剪；容量上升时，除最低基数规则外不会立即增加数量。

自然资源按当前数量指数繁衍，并在环境容量处封顶：

```text
繁衍量 =
    当前数量
  × 资源基础繁衍率
  × 当地适应系数
```

```text
繁衍后的数量 = min(
    自然资源最大容量,
    当前数量 + 繁衍量
)
```

只有超过最低繁衍基数的部分能够形成经济产出潜力：

```text
可采集数量 = max(
    0,
    当前数量 - 实际最低数量
)
```

```text
自然资源月度产出潜力 =
    可采集数量
  × 资源单位产出
```

实际采集仍需后续人文系统提供劳动力、工具和采集方式；这些机制不属于地块自然属性。

- 自然资源每月先繁衍、后采集；繁衍后的数量作为采集阶段的当前数量。
- 实际采集数量不能超过可采集数量；被采集的数量按资源单位产出转化为产品，并从当前数量中扣除。
- 采集后剩余的数量成为结算后的当前数量；未发生采集时，繁衍后的数量直接成为结算后的当前数量。

### 农作物

农作物模板提供作物自身的通用参数：

```text
CropTemplate
- unitOutput
- unitMonthlyRichnessConsumption
```

农田覆盖率与作物面积分开保存。每种作物的面积比例表示它在农田中的占比：

```text
Σ 作物面积比例 ≤ 1
```

```text
作物实际覆盖率 =
    农田覆盖率
  × 作物面积比例
```

农作物由人为种植和维持，不模拟独立的自然繁衍状态。其当前数量始终等于自然条件允许的容量：

```text
作物当前数量 =
    当前丰容度
  × 作物实际覆盖率
  × 当地适应系数
```

```text
作物月度产出 =
    作物当前数量
  × 作物单位产出
```

```text
作物月度丰容消耗 =
    作物当前数量
  × 作物单位月度丰容消耗
```

```text
下一月丰容度 = clamp(
    当前丰容度
  + 丰容自然恢复
  - Σ 作物月度丰容消耗,
    0,
    最大丰容度
)
```

- 丰容越低，作物当前数量、产出和消耗都会同步下降。
- 长期种植通常形成正数的动态平衡，而不是将地块丰容度清空。
- 丰容度下降不会自动减少作物面积或农田面积；是否停种、休耕或弃耕属于人文决策。
- 休耕地没有作物数量、产出或丰容消耗，但仍占用农田覆盖率并排除自然资源容量。

### 水系与水体

- 水系是独立的有向网络，不是地块或边的附属状态。
- 一个水系可以包含多条河流；河段属于河流，河流属于水系。
- 河段沿地块边流动，在地块顶点汇流，并引用对应地图边。
- 边到河段的映射只是派生查询索引。
- 河段使用固定三级规模：`Minor / Regional / Major`。
- 同一水系中的不同河段可以拥有不同规模；第一版不模拟动态流量、洪水、枯水期或河道变化。
- 湖泊由独立水体对象表达；水体对象不保存整个湖泊或海洋共享的资源池。
- 水系与湖泊的丰容修正只作用于相邻陆地地块，不作用于水域地块本身。
- 每个水系和每个湖泊对同一地块最多产生一次修正，不按相邻边或水域格数量重复计算。
- 同一水系通过多条河流或多个河段接触一个地块时，使用这些局部河段中的最高规模修正。
- 所有湖泊使用相同的固定丰容修正值。
- 不同水系和不同湖泊的修正可以分别累加。

### 矿藏

- 矿藏是绑定单个地块的稀疏对象；单格可以拥有多个矿藏。
- 跨区域矿带拆分为相邻地块中的独立矿藏。
- 矿藏记录矿种、初始储量、剩余储量和天然开采难度。
- 矿石品位第一版合并进天然开采难度。
- 矿藏不可恢复，不使用生物群落或自然资源繁衍机制。

### 初始状态与数据规模

- 默认世界从未受人类破坏的自然平衡状态开始。
- 初始当前丰容度等于最大丰容度。
- 初始自然资源数量等于各自最大容量。
- 特定历史剧本以后可以覆盖农田、建设用地、当前丰容度和资源数量。
- 普遍属性使用连续紧凑数组。
- 自然资源只为所属群落列出的资源分配状态槽位。
- 水系、河流、矿藏和水体使用稀疏对象。
- 数字运行时 ID 不作为持久身份；地图和存档保存稳定键映射表。

## 城市与省份

- 城市由玩家动态指定的一组地块组成，可以扩张、缩小、合并或拆分。
- 省份由玩家指定的一组城市组成。
- 人口、土地、资源和经济状态保存在地块层，以保证城市边界变化时数据不会丢失。
- 城市和省份保存地块数据的汇总；边界变化时增量更新汇总。

## 时间与结算

- 玩家操作实时生效。
- 军事系统每日结算。
- 人口与经济系统每月结算。
- 月度经济结算以地块为基础，再汇总到城市和省份。

## 第一版范围

- 优先实现会直接影响发展、经济和战争的自然属性。
- 地形和基础地理结构保持静态。
- 环境变化采用简化模型；海岸演变、河流改道、侵蚀等非核心长期变化暂不实现。
- 经济结算采用面向连续数据的批量计算，避免为每个地块建立重量级模拟对象。
