# 设计方案

本文记录已确认的领域规则、系统边界和关键方案，是后续设计与实现的依据。实现现状不反向定义设计约束；待决事项不视为已确认规则。

只有领域规则、系统边界或关键方案发生变化时才更新本文。代码组织、调用流程、默认参数、调试操作、开发进度和变更历史不在本文范围内。

## 设计目标与第一版边界

- 游戏以全球球面地图为基础，时间跨度覆盖数千年的人类文明发展。
- 现实地图只约束自然地理；城市、省份、人口、经济与政治由游戏过程产生。
- 自然地理包括地形、气候、水文、生物群落、自然资源和矿藏，为发展、经济与战争提供条件。
- 第一版使用无高程球面。地形、海陆和水深具有玩法意义，通过地图颜色和贴合球面的覆盖效果表达，不改变球面几何。
- 地形与基础地理结构保持静态；不模拟海岸演变、河道变化、侵蚀或动态地形。
- 环境变化采用下文规定的丰容恢复、资源繁衍和土地使用机制，不模拟长期气候迁移、生态演替或物种灭绝。

## 空间模型与系统边界

### 地块尺度与拓扑

- 地块是最小的地理、状态和操作单元；移动、战争和领土操作均以地块为边界。道路连接相邻地块。
- 逻辑网格采用频率为 358 的固定细分二十面体，共有 1,281,642 个地块，其中陆地约 38 万个。每格平均面积约 400 km²，决定玩法的空间尺度。
- 细分顶点作为地块中心，三角网采用球面 Delaunay 拓扑；地块边界采用其球面 Voronoi 对偶，角点为三角形球面外心，边为相邻角点间的大圆弧。
- 网格包含 12 个五边形，其余为六边形。五边形不使用特殊玩法类型，在规则上视为与六边形等面积；陆地不设置特殊的“空地块”类型。
- 第一版不做 Lloyd 松弛。拓扑必须满足 Delaunay 条件、角点方向和地块有效性要求。
- 地块标识（TileId）、邻接关系和球面查询结果必须可重现。地块身份在世界生命周期内稳定，不随世界朝向、相机位置或显示细节变化。
- 编号约定的变化必须显式处理地图和存档兼容，不能让同一标识静默指向不同地块。

### 职责与数据交换

- 球面渲染负责几何、LOD 和可见性；网格负责地块拓扑、空间查询及地块显示数据；玩法层负责状态演进和颜色所代表的含义。
- 球面渲染与网格彼此独立，不持有对方的业务对象。共享图形资源由统一入口管理，各单元管理自身生成的资源。
- 地块查询以球面方向为输入，返回真实地块身份。玩法逻辑不依赖渲染结果或 GPU 回读。
- 显示数据以 `TileId -> display color` 映射交换。渲染无需知道颜色代表地形、政治、气候、资源还是动态状态。
- 地形、政治、气候和资源等地图模式都以地块为最小语义着色单位。边界可以按屏幕尺度渐隐或隐藏，但不能用近似地块替换真实语义。

### 球面显示方案

- 球面采用等角 Cube-sphere，以六个面的四叉树划分组织局部渲染。空间划分可由球面形状推导，不作为世界地理资产保存。
- 可见区域共享规则几何，按网格区间的估算屏幕尺寸选择统一 LOD。第一版不采用混合层级；层级切换应稳定，相邻区域不能出现空洞或明显接缝。
- 可见性裁剪和 LOD 只控制显示成本，不改变地块身份、邻接或地图属性。
- 地块颜色由 GPU 根据球面方向确定地块归属后读取；显示与拾取不另建覆盖全球的完整地块 Mesh。
- 几何精度与查询优化以正确的地块归属和可接受的视觉精度为准。

## 自然地理与资源规则

本节记录自然地块属性与机制。采集强度、劳动力、技术、设施和资源发现等人文机制不在本节范围内。

- 气候和生物群落模板在第一版中固定。
- 地形、气候、生物群落、自然资源和作物的分类及参数由数据模板定义。

### 地形与土地使用

所有地块共用平原、丘陵、山地、浅水和深水五种地形分类。

- 陆地类型表达地表起伏，水域类型表达深度；这些都是玩法和地图模式属性，不改变球面几何。
- 海洋和湖泊身份由独立水体对象表达；沿海由陆地与水域邻接推导。
- 地形模板提供可开发面积比例。
- 农田与建设用地共享可开发面积上限；道路、矿山等小型设施第一版不计占地。

```text
农田覆盖率 + 建设用地覆盖率 ≤ 地形可开发面积比例 ≤ 1
```

```text
自然覆盖率 = 1 - 农田覆盖率 - 建设用地覆盖率
```

- 自然覆盖率是派生值，不单独保存。
- 不设置“恢复中的裸露土地”或自然覆盖恢复机制。
- 农田中没有种植作物的部分是休耕地，仍属于农田，不计入自然覆盖。
- 停种只形成休耕；明确弃耕才减少农田覆盖率。
- 弃耕或废弃建设用地会立即扩大自然资源的环境容量，但资源数量仍需通过繁衍恢复。

### 气候与丰容度

每个地块引用一个固定的气候模板，提供基础最大丰容度、丰容恢复率，以及逐月的移动和军事季节系数。

- 丰容度是非负的抽象环境容量值，不归一化到 `0～1`，也不设置统一数值上限。
- 水系与湖泊提高相邻陆地地块的最大丰容度。
- 南北半球可以通过月份偏移复用气候模板的军事和移动季节系数。
- 农作物与自然资源的产出均采用月度平均值，不设置各自的月度产出周期。

```text
最大丰容度 = max(
    0,
    气候基础最大丰容度
  + Σ 去重后的水系修正
  + Σ 去重后的湖泊修正
)
```

```text
0 ≤ 当前丰容度 ≤ 最大丰容度
```

```text
丰容自然恢复 =
    气候丰容恢复率
  × (最大丰容度 - 当前丰容度)
```

丰容恢复随缺口缩小而逐渐减慢。自然资源种群的繁衍使用另一套指数增长机制，不使用丰容缺口公式。

### 生物群落与适应系数

陆地和水域地块共用同一套生物群落机制，只承载不同模板数据。

生物群落规定当地自然资源和适宜作物的种类，并为每一种资源或作物指定适应系数。

- 自然资源条目表示游戏级资源种群，例如木材植被、野味动物、药用植物和渔业生物，不表示真实生物学物种。
- 适应系数表示该资源种群或作物在当地的生长活跃程度。
- 适应系数参与环境容量；对于自然资源，还参与繁衍速度。
- 水域生物群落可以拥有渔业等自然资源，适宜作物列表第一版为空。
- 群落中不存在的作物，其自然适应系数视为零。未来技术或设施可以覆盖该自然限制。

### 自然资源种群

自然资源模板规定资源的单位产出和基础繁衍率。

地块只为所属生物群落列出的自然资源保存当前数量。

```text
自然资源最大容量 =
    当前丰容度
  × 自然覆盖率
  × 当地适应系数
```

所有自然资源共享一个全局固定的最低繁衍基数：

```text
实际最低数量 = min(
    全局最低繁衍基数,
    自然资源最大容量
)
```

```text
实际最低数量 ≤ 当前数量 ≤ 自然资源最大容量
```

- 最低繁衍基数是当前数量的有效下限，不另设隐藏状态或零丰度状态。
- 最低繁衍基数不可采集，也不产生资源产出。
- 环境容量降至低于最低基数时，实际最低数量随容量降低；容量为零时数量才为零。
- 环境容量恢复到高于固定基数时，当前数量自动提升到固定基数，用来抽象残存种群、种子和邻近迁入。
- 环境容量下降时，超过新上限的数量立即裁剪；容量上升时，除最低基数规则外不会立即增加数量。

自然资源按当前数量指数繁衍，并在环境容量处封顶：

```text
繁衍量 =
    当前数量
  × 资源基础繁衍率
  × 当地适应系数
```

```text
繁衍后的数量 = min(
    自然资源最大容量,
    当前数量 + 繁衍量
)
```

只有超过最低繁衍基数的部分能够形成经济产出潜力：

```text
可采集数量 = max(
    0,
    当前数量 - 实际最低数量
)
```

```text
自然资源月度产出潜力 =
    可采集数量
  × 资源单位产出
```

实际采集仍需后续人文系统提供劳动力、工具和采集方式；这些机制不属于地块自然属性。

- 自然资源每月先繁衍、后采集；繁衍后的数量作为采集阶段的当前数量。
- 实际采集数量不能超过可采集数量；被采集的数量按资源单位产出转化为产品，并从当前数量中扣除。
- 采集后剩余的数量成为结算后的当前数量；未发生采集时，繁衍后的数量直接成为结算后的当前数量。

### 农作物

农作物模板规定作物的单位产出和单位月度丰容消耗。

农田覆盖率与作物面积是不同的概念。每种作物的面积比例表示它在农田中的占比：

```text
Σ 作物面积比例 ≤ 1
```

```text
作物实际覆盖率 =
    农田覆盖率
  × 作物面积比例
```

农作物由人为种植和维持，不模拟独立的自然繁衍状态。其当前数量始终等于自然条件允许的容量：

```text
作物当前数量 =
    当前丰容度
  × 作物实际覆盖率
  × 当地适应系数
```

```text
作物月度产出 =
    作物当前数量
  × 作物单位产出
```

```text
作物月度丰容消耗 =
    作物当前数量
  × 作物单位月度丰容消耗
```

```text
下一月丰容度 = clamp(
    当前丰容度
  + 丰容自然恢复
  - Σ 作物月度丰容消耗,
    0,
    最大丰容度
)
```

- 丰容越低，作物当前数量、产出和消耗都会同步下降。
- 长期种植通常形成正数的动态平衡，而不是将地块丰容度清空。
- 丰容度下降不会自动减少作物面积或农田面积；是否停种、休耕或弃耕属于人文决策。
- 休耕地没有作物数量、产出或丰容消耗，但仍占用农田覆盖率并排除自然资源容量。

### 水系与水体

- 水系是独立的有向网络，不是地块或边的附属状态。
- 一个水系可以包含多条河流；河段属于河流，河流属于水系。
- 每个河段占用一条地块边，方向为上游到下游；河段在地块顶点汇流，并保持明确的上下游关系。
- 河段使用固定三级规模：小型、区域级和大型。
- 同一水系中的不同河段可以拥有不同规模；第一版不模拟动态流量、洪水、枯水期或河道变化。
- 水系与湖泊的丰容修正只作用于相邻陆地地块，不作用于水域地块本身。
- 每个水系和每个湖泊对同一地块最多产生一次修正，不按相邻边或水域格数量重复计算。
- 同一水系通过多条河流或多个河段接触一个地块时，使用这些局部河段中的最高规模修正。
- 所有湖泊使用相同的固定丰容修正值。
- 不同水系和不同湖泊的修正可以分别累加。

水体区分海洋和湖泊，并确定所属水域地块或接触的陆地地块。资源状态归属于地块，水体不形成跨地块共享资源池。

海峡是海上移动网络中的双向附加连接，关联两端地块、航行路径、宽度和通航等级。海峡独立于有向水系，防止地块尺度掩盖重要航道。

### 矿藏

- 矿藏绑定单个地块；单格可以拥有多个矿藏。
- 跨区域矿带拆分为相邻地块中的独立矿藏。
- 矿藏记录矿种、初始储量、剩余储量和天然开采难度。
- 矿石品位第一版合并进天然开采难度。
- 矿藏不可恢复，不使用生物群落或自然资源繁衍机制。

### 初始状态

- 默认世界从未受人类破坏的自然平衡状态开始。
- 初始当前丰容度等于最大丰容度。
- 初始自然资源数量等于各自最大容量。
- 特定历史剧本以后可以覆盖农田、建设用地、当前丰容度和资源数量。

## 人文组织与时间推进

### 城市与省份

- 城市由玩家动态指定的一组地块组成，可以扩张、缩小、合并或拆分。
- 省份由玩家指定的一组城市组成。
- 人口、土地、资源和经济状态归属于地块，城市边界变化不能使这些状态丢失。
- 城市和省份的数据由所属地块汇总，边界变化后必须保持一致。

### 结算周期

- 玩家操作实时生效。
- 军事系统每日结算。
- 人口与经济系统每月结算。
- 月度经济结算以地块为基础，再汇总到城市和省份。
- 全球规模的模拟采用批量处理，不要求每个地块成为独立运行的模拟对象。

## 世界数据构建原则

离线构建把现实自然地理投影到固定逻辑地块，生成玩法属性与水文拓扑。高程作为分类依据，不进入运行时球面几何。

### 地块分类依据

- 数据投影须保持统一地理基准，正确处理日期变更线两侧的连续关系。
- 海陆边界与湖泊范围共同确定水体身份。高程正负不能直接判定水体，海岸两侧的陆地和海底样本不能混合平均后分类。
- 海深暂以 200 m 为浅海与深海分界，接入真实数据后复核。
- 陆地地貌依据地块范围内的高程、坡度和局部起伏确定；分类阈值由真实数据分布校准。

### 水文与航行连通

- 河流按流量、上游面积和河序筛选，保留对显示或玩法有意义的河流；规模根据流量或河序划分。
- 河段映射到地块边时，必须保留源数据中的上下游关系、入海或内流终点，不能由映射后的几何反推流向。河网不得因映射产生断流、逆流或错误汇流。
- 湖泊通过范围和出水口对接河网。默认保留面积至少约 20 km² 的湖泊，位于保留河网或具有玩法意义的小湖可以例外；面积阈值仍需数据校准。
- 人工水库默认排除；经过人工调控的天然湖泊保留天然湖形，不引入现代调蓄语义。
- 大湖可以占据水域地块，小湖以与陆地地块的接触关系表达；湖泊出水口须与河网一致。
- 重要海峡保留独立的双向航行连接，避免地块分类使原有航道失去连通性。

### 持久身份与可重现性

- 地图资产保存地块的自然属性、水体、有向河网、航行连接及其与地块、边、角点的关系。可推导的渲染数据和原始高分辨率源数据不作为玩法资产内容。
- 模板和源要素使用稳定键持久化；运行时临时编号不能替代持久身份。地图和存档必须保留必要的身份映射。
- 数据来源必须可追溯，记录版本、校验和、地理基准、许可和引用要求；无需自动追踪最新版本，但相同输入和规则必须能够重现构建结果。
- 数据源或派生规则变化后须重新构建；资产格式、编号或语义变化时须明确版本及兼容关系。

## 待决设计问题

- 地块边和角点的稳定身份约定，以及逻辑拓扑采用预生成资产还是运行时生成。
- 各地图模式的颜色语义、地块选择反馈，以及边界显示随屏幕尺度变化的规则。
- 基于真实数据确定陆地地貌阈值、河流保留标准、湖泊最小面积、水域地块覆盖阈值和河流规模划分。
