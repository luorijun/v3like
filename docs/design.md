# 设计方案

本文记录已确认的领域规则、系统边界和关键方案，是后续设计与实现的依据。实现现状不反向定义设计约束；待决事项不视为已确认规则。

只有领域规则、系统边界或关键方案发生变化时才更新本文。代码组织、调用流程、默认参数、调试操作、开发进度和变更历史不在本文范围内。

## 设计目标与第一版边界

- 游戏以全球球面地图为基础，时间跨度覆盖数千年的人类文明发展。
- 现实地图只约束自然地理；城市、省份、人口、经济与政治由游戏过程产生。
- 自然地理包括地形、气候、水文、生物群落、自然资源和矿藏，为发展、经济与战争提供条件。
- 第一版使用无高程球面。地形、海陆和水深具有玩法意义，通过地图颜色和贴合球面的覆盖效果表达，不改变球面几何。
- 地形与基础地理结构保持静态；不模拟海岸演变、河道变化、侵蚀或动态地形。
- 环境变化采用下文规定的丰容恢复、资源繁衍和土地使用机制，不模拟长期气候迁移、生态演替或物种灭绝。

## 空间模型与系统边界

### 地块尺度与拓扑

- 地块是最小的地理、状态和操作单元；移动、战争和领土操作均以地块为边界。道路连接相邻地块。
- 逻辑网格采用频率为 358 的固定细分二十面体，共有 1,281,642 个地块，其中陆地约 38 万个。每格平均面积约 400 km²，决定玩法的空间尺度。
- 细分顶点作为地块中心，三角网采用球面 Delaunay 拓扑；地块边界采用其球面 Voronoi 对偶，角点为三角形球面外心，边为相邻角点间的大圆弧。
- 网格包含 12 个五边形，其余为六边形。五边形不使用特殊玩法类型，在规则上视为与六边形等面积；陆地不设置特殊的“空地块”类型。
- 第一版不做 Lloyd 松弛。拓扑必须满足 Delaunay 条件、角点方向和地块有效性要求。
- 地块标识（TileId）、邻接关系和球面查询结果必须可重现。地块身份在世界生命周期内稳定，不随世界朝向、相机位置或显示细节变化。
- 编号约定的变化必须显式处理地图和存档兼容，不能让同一标识静默指向不同地块。

### 职责与数据交换

- 球面渲染负责几何、LOD 和可见性；网格负责地块拓扑、空间查询及地块显示数据；玩法层负责状态演进和颜色所代表的含义。
- 球面渲染与网格彼此独立，不持有对方的业务对象。共享图形资源由统一入口管理，各单元管理自身生成的资源。
- 地块查询以球面方向为输入，返回真实地块身份。玩法逻辑不依赖渲染结果或 GPU 回读。
- 显示数据以 `TileId -> display color` 映射交换。渲染无需知道颜色代表地形、政治、气候、资源还是动态状态。
- 地形、政治、气候和资源等地图模式都以地块为最小语义着色单位。边界可以按屏幕尺度渐隐或隐藏，但不能用近似地块替换真实语义。

### 球面显示方案

- 球面采用等角 Cube-sphere，以六个面的四叉树划分组织局部渲染。空间划分可由球面形状推导，不作为世界地理资产保存。
- 可见区域共享规则几何，按网格区间的估算屏幕尺寸选择统一 LOD。第一版不采用混合层级；层级切换应稳定，相邻区域不能出现空洞或明显接缝。
- 可见性裁剪和 LOD 只控制显示成本，不改变地块身份、邻接或地图属性。
- 地块颜色由 GPU 根据球面方向确定地块归属后读取；显示与拾取不另建覆盖全球的完整地块 Mesh。
- 几何精度与查询优化以正确的地块归属和可接受的视觉精度为准。

## 自然地理

本章按自然数据的职责组织设计，分别说明数据源、抽象模型、处理流程和使用方式。未确定的数据源与算法在对应章节标为待完善，不预设获取或处理方案。

- 海陆归属、地貌、气候、生物群落和矿藏分别表达不同属性，不合并为复合类型；属性之间可以存在生成依赖和玩法联系。
- 气候和生物群落模板在第一版中固定。
- 地形、气候、生物群落、自然资源和作物的分类及参数由数据模板定义。
- 自然生物与农作物共同纳入生物群落设计，按共享生长机制及差异规则组织，不按自然或人为来源割裂设计。
- 河流、海峡和运河共用映射到网格边并记录为独立实体的空间表达；数据源和具体语义分别说明。
- 本章包含土地使用对生长环境的影响；土地分配决策、劳动力、技术、设施和资源发现等人文机制由后续系统负责。

### 海陆区分与地块归属

#### 数据源

采用 GSHHG 的 GMT `earth_mask_01m_g` 全球归属栅格，分辨率为 1 角分、节点配准，确定陆地、海洋和湖泊身份。该产品省略面积约 3 km² 以下的地物。

归属数据用于区分地表身份，不等同于完整的独立湖泊实体数据；湖泊实体所需来源在湖泊章节单独说明。

#### 抽象模型与参数

- 地块归属区分陆地、海洋和湖泊，与地貌分类分别表达。
- 海洋和湖泊由独立水体对象表达，并关联所属水域地块或接触的陆地地块；海洋对象的划分与具体结构待完善。
- 沿海关系由陆地与海洋的邻接推导；邻接湖泊不等同于沿海。
- 小湖可以只关联接触的陆地地块，不要求将整个地块改为湖泊。

#### 数据处理与展示

- 先根据归属数据确定地块身份，再分别生成陆地起伏或水域深度分类。
- 第一版按固定地块中心最近邻采样，混合地块以中心样本决定归属。源值 0 归为海洋，1、3 归为陆地，2、4 归为湖泊；分类不插值、不平均、不舍入。
- 中心采样不保证保留小岛、小湖或狭窄水域，也不保证航道连通；三类归属不包含独立水体身份与实体关系。
- 高程正负不能决定海陆身份；低于海平面的陆地仍是陆地，高海拔湖泊仍是湖泊。
- 归属结果由专门的地图模式展示，区分陆地、海洋和湖泊，不使用高程色带替代身份。
- 归属模式使用固定颜色：陆地绿色、海洋深蓝、湖泊青蓝。

#### 待完善

- 后续覆盖统计及混合地块归属规则的改进。
- 小岛、小湖和狭窄水域在地块尺度上的保留方式。
- 归属数据与独立湖泊范围不一致时的处理规则。
- 归属属性与水体实体的具体存储关系。

### 地貌

#### 数据源

高程与海底高程采用 GMT `earth_relief`。用于分类的数据分辨率及采样尺度待完善；具体资产生成操作与现有输入记录见 [README](../README.md)。

湖泊水深的数据依据尚未确定，不以湖面绝对海拔推导湖泊水深。

#### 抽象模型与参数

- 保留平原、丘陵、山地、浅水和深水五种地形分类。陆地类型表达地表起伏，水域类型表达深度。
- 分类是玩法和地图模式属性，不改变球面几何；海洋地块只需浅深分类，不要求保留连续海底起伏。
- 地形模板提供可开发面积比例，供土地使用和生长容量计算使用。
- 浅深水表达水深，不等同于近岸或远洋等航行条件。

#### 数据处理与使用

- 陆地地貌依据地块范围内的高程、坡度和局部起伏确定，不仅按中心点绝对海拔分类。
- 海岸两侧的陆地与海底样本不能混合平均后分类。
- 海深暂以 200 m 为浅海与深海分界，接入真实数据后复核；该值不是已校准的最终阈值。
- 分类结果供地貌展示及玩法规则使用，原始高程不进入运行时球面几何。

#### 待完善

- 地块内采样、起伏统计方法及分类阈值。
- 高程与归属数据在边界处冲突时的处理。
- 湖泊浅深分类的数据来源和方法。
- 高原是否需要独立类型、湿地如何表达，尚未形成新增分类的决定。

### 气候

#### 数据源与地块生成

数据源、气候分类体系以及从源数据生成地块气候引用的算法待完善，不预设获取、推导或映射方式。

#### 抽象参数与环境作用

每个地块引用一个固定的气候模板，提供基础最大丰容度、丰容恢复率，以及逐月的移动和军事季节系数。

- 丰容度是非负的抽象环境容量值，不归一化到 `0～1`，也不设置统一数值上限。
- 水系与湖泊提高相邻陆地地块的最大丰容度。
- 南北半球可以通过月份偏移复用气候模板的军事和移动季节系数。
- 农作物与自然资源的产出均采用月度平均值，不设置各自的月度产出周期。

```text
最大丰容度 = max(
    0,
    气候基础最大丰容度
  + Σ 去重后的水系修正
  + Σ 去重后的湖泊修正
)
```

```text
0 ≤ 当前丰容度 ≤ 最大丰容度
```

```text
丰容自然恢复 =
    气候丰容恢复率
  × (最大丰容度 - 当前丰容度)
```

丰容恢复随缺口缩小而逐渐减慢。自然资源种群的繁衍使用另一套指数增长机制，不使用丰容缺口公式。

#### 待完善

- 气候模板的具体分类、参数值及地块分配方式。
- 季节系数的月份偏移规则。

### 生物群落

#### 数据源与地块生成

群落分布的数据源、分类体系、地块分配算法，以及资源和作物参数的确定方式待完善。自然生物与农作物可以使用不同来源，不预设具体获取与处理方式。

#### 群落组成与抽象参数

陆地和水域地块共用同一套生物群落机制，只承载不同模板数据。

生物群落规定当地自然资源和适宜作物的种类，并为每一种资源或作物指定适应系数。

- 自然资源条目表示游戏级资源种群，例如木材植被、野味动物、药用植物和渔业生物，不表示真实生物学物种。
- 适应系数表示该资源种群或作物在当地的生长活跃程度。
- 适应系数参与环境容量；对于自然资源，还参与繁衍速度。
- 水域生物群落可以拥有渔业等自然资源，适宜作物列表第一版为空。
- 群落中不存在的作物，其自然适应系数视为零。未来技术或设施可以覆盖该自然限制。

农作物属于本章的生物群落设计范围。群落适应性、环境容量、生长和产出是自然生物与农作物的共同设计基础；种植、维持与采集方式的差异在共同机制下分别说明。

#### 共同生长基础与待完善边界

自然生物与农作物的容量均由当前丰容度、各自占用的面积比例和当地适应系数共同决定，产出均与可产出的数量及单位产出有关。两者的产出均采用月度平均值。

下文保留已有的自然繁衍和农作物计算规则，作为继续完善共同生长机制的依据：自然资源保存数量并繁衍，农作物目前按容量直接计算数量。两者如何统一数量状态、生长过程和收获后的恢复仍待完善，不能视为已经采用相同的完整生长公式。

#### 土地使用与生长面积

- 农田与建设用地共享可开发面积上限；道路、矿山等小型设施第一版不计占地。

```text
农田覆盖率 + 建设用地覆盖率 ≤ 地形可开发面积比例 ≤ 1
```

```text
自然覆盖率 = 1 - 农田覆盖率 - 建设用地覆盖率
```

- 自然覆盖率是派生值，不单独保存。
- 不设置“恢复中的裸露土地”或自然覆盖恢复机制。
- 农田中没有种植作物的部分是休耕地，仍属于农田，不计入自然覆盖。
- 停种只形成休耕；明确弃耕才减少农田覆盖率。
- 弃耕或废弃建设用地会立即扩大自然资源的环境容量，但资源数量仍需通过繁衍恢复。

#### 自然资源种群

自然资源模板规定资源的单位产出和基础繁衍率。

地块只为所属生物群落列出的自然资源保存当前数量。

```text
自然资源最大容量 =
    当前丰容度
  × 自然覆盖率
  × 当地适应系数
```

所有自然资源共享一个全局固定的最低繁衍基数：

```text
实际最低数量 = min(
    全局最低繁衍基数,
    自然资源最大容量
)
```

```text
实际最低数量 ≤ 当前数量 ≤ 自然资源最大容量
```

- 最低繁衍基数是当前数量的有效下限，不另设隐藏状态或零丰度状态。
- 最低繁衍基数不可采集，也不产生资源产出。
- 环境容量降至低于最低基数时，实际最低数量随容量降低；容量为零时数量才为零。
- 环境容量恢复到高于固定基数时，当前数量自动提升到固定基数，用来抽象残存种群、种子和邻近迁入。
- 环境容量下降时，超过新上限的数量立即裁剪；容量上升时，除最低基数规则外不会立即增加数量。

自然资源按当前数量指数繁衍，并在环境容量处封顶：

```text
繁衍量 =
    当前数量
  × 资源基础繁衍率
  × 当地适应系数
```

```text
繁衍后的数量 = min(
    自然资源最大容量,
    当前数量 + 繁衍量
)
```

只有超过最低繁衍基数的部分能够形成经济产出潜力：

```text
可采集数量 = max(
    0,
    当前数量 - 实际最低数量
)
```

```text
自然资源月度产出潜力 =
    可采集数量
  × 资源单位产出
```

实际采集仍需后续人文系统提供劳动力、工具和采集方式；这些机制不属于地块自然属性。

- 自然资源每月先繁衍、后采集；繁衍后的数量作为采集阶段的当前数量。
- 实际采集数量不能超过可采集数量；被采集的数量按资源单位产出转化为产品，并从当前数量中扣除。
- 采集后剩余的数量成为结算后的当前数量；未发生采集时，繁衍后的数量直接成为结算后的当前数量。

#### 农作物

农作物模板规定作物的单位产出和单位月度丰容消耗。

农田覆盖率与作物面积是不同的概念。每种作物的面积比例表示它在农田中的占比：

```text
Σ 作物面积比例 ≤ 1
```

```text
作物实际覆盖率 =
    农田覆盖率
  × 作物面积比例
```

农作物由人为种植和维持，不模拟独立的自然繁衍状态。其当前数量始终等于自然条件允许的容量：

```text
作物当前数量 =
    当前丰容度
  × 作物实际覆盖率
  × 当地适应系数
```

```text
作物月度产出 =
    作物当前数量
  × 作物单位产出
```

```text
作物月度丰容消耗 =
    作物当前数量
  × 作物单位月度丰容消耗
```

```text
下一月丰容度 = clamp(
    当前丰容度
  + 丰容自然恢复
  - Σ 作物月度丰容消耗,
    0,
    最大丰容度
)
```

- 丰容越低，作物当前数量、产出和消耗都会同步下降。
- 长期种植通常形成正数的动态平衡，而不是将地块丰容度清空。
- 丰容度下降不会自动减少作物面积或农田面积；是否停种、休耕或弃耕属于人文决策。
- 休耕地没有作物数量、产出或丰容消耗，但仍占用农田覆盖率并排除自然资源容量。

#### 待完善

- 生物群落模板、自然资源及作物的具体分类与参数。
- 共同生长模型的数据结构、数量状态、增长及采集或收获后的恢复规则。
- 明确哪些差异需要保留，哪些规则可以共用；在此之前不因章节合并而擅自统一公式。

### 矿藏资源

#### 数据源与生成流程

数据源、矿藏空间分配、跨区域矿带拆分算法及初始储量和难度的生成方式待完善，不预设来源与处理方法。

#### 实体与抽象参数

- 矿藏绑定单个地块；单格可以拥有多个矿藏。
- 跨区域矿带拆分为相邻地块中的独立矿藏。
- 矿藏记录矿种、初始储量、剩余储量和天然开采难度。
- 矿石品位第一版合并进天然开采难度。
- 矿藏不可恢复，不使用生物群落或自然资源繁衍机制。

#### 使用与待完善

矿藏为后续发现和开采系统提供地块级资源条件。矿藏的稳定身份、参数尺度和展示方式待完善；发现、技术及设施不由天然开采难度一项包办。

### 水道与水系

#### 数据源

河流、海峡和运河分别确定数据源，不要求来自同一数据集。目前均待完善，不预设下载、提取或人工整理流程。

#### 共同空间模型

- 河流、海峡和运河都将现实水道映射到规则网格边，并保存为具有稳定身份的独立实体，不只是地块或边上的附属状态。
- 水道实体需要关联映射后的边路径及连接关系；具体字段、路径组织和端点结构待完善。
- 共享边路径表达不意味着共享所有水文或航行规则。河流上下游方向与通航方向分别表达，不能互相替代。
- 同一网格边承载多个源要素或不同水道时的组织方式待完善，不预设一条边只能对应一个水道实体。

#### 河流与水系的抽象模型

- 水系是独立的有向网络；一个水系可以包含多条河流，河段属于河流，河流属于水系。
- 每个河段占用一条地块边，方向为上游到下游；河段在地块角点汇流，并保持明确的上下游关系。
- 河段使用固定三级规模：小型、区域级和大型。同一水系中的不同河段可以拥有不同规模。
- 第一版不模拟动态流量、洪水、枯水期或河道变化。
- 水系、河流、河段的稳定身份、引用关系和终点表示仍需落实为具体数据结构。

#### 海峡与运河的抽象模型

- 海峡与运河同样需要独立实体及网格边路径，不能只用跨地块的附加连接替代其空间表达。
- 海峡保留双向航行连接的语义，关联两端地块、航行路径、宽度和通航等级；这些信息如何与边路径结合待完善。
- 运河的参数、通航规则及与其他水道的连接结构待完善，不直接套用河流的上下游和规模规则。
- 运河数据的时代范围及其与世界初始状态、后续人为建设的关系待完善；不能默认导入全部现代运河。

#### 数据处理与连通约束

- 河流筛选考虑流量、上游面积和河序，保留对显示或玩法有意义的河流；规模划分考虑流量或河序。具体标准需结合最终数据源确定。
- 河段映射到地块边时，必须保留源数据中的上下游关系、入海或内流终点，不能由映射后的几何反推流向。
- 河网不得因映射产生断流、逆流或错误汇流；与湖泊的连接须保持一致。
- 海峡和运河映射需要保留其连接作用，避免地块尺度使重要航道失去连通性。
- 边路径选择、汇流与端点匹配、多个要素竞争同一边时的处理算法均待完善。

#### 环境作用与待完善

- 河流水系的丰容修正只作用于相邻陆地地块，不作用于水域地块本身。
- 每个水系对同一地块最多产生一次修正，不按相邻边重复计算；通过多条河流或多个河段接触时，使用局部河段中的最高规模修正。
- 不同水系的修正可以累加，并与湖泊修正分别累加。
- 海峡、运河是否产生环境修正，以及水道的具体显示和通航规则待完善，不能由共用空间模型直接推定。

### 湖泊

#### 数据源

独立湖泊实体的数据源及获取方式待完善。GSHHG 负责地块归属，不视为已解决湖泊实体身份、出水口、河湖关联及水深的全部来源。

#### 实体与抽象参数

- 湖泊以独立水体实体记录，需要表达稳定身份、范围、所属水域地块、接触的陆地地块以及河湖连接关系；具体字段和存储结构待完善。
- 湖泊不需要沿网格边拟合为水道路径，但仍需建立范围与地块的关联。
- 大湖可以占据水域地块，小湖以与陆地地块的接触关系表达。
- 资源状态归属于地块，水体不形成跨地块共享资源池。

#### 数据处理约束

- 湖泊通过范围和出水口对接河网，出水口须与河网一致；具体对接算法待完善。
- 暂以面积至少约 20 km² 作为保留湖泊的起点；位于保留河网或具有玩法意义的小湖可以例外，阈值需数据校准。
- 人工水库默认排除；经过人工调控的天然湖泊保留天然湖形，不引入现代调蓄语义。天然湖形如何取得待完善。

#### 环境作用与待完善

- 所有湖泊使用相同的固定丰容修正值，只作用于接触的陆地地块，不作用于水域地块本身。
- 每个湖泊对同一地块最多产生一次修正，不按相邻水域格数量重复计算；不同湖泊的修正可以累加。
- 湖泊实体结构、保留标准、范围与地块关联算法及河湖连接算法待完善。
- 与地块归属数据的一致性处理见海陆区分章节；湖泊水深分类见地貌章节。

### 初始状态

- 默认世界从未受人类破坏的自然平衡状态开始。
- 初始当前丰容度等于最大丰容度。
- 初始自然资源数量等于各自最大容量。
- 特定历史剧本以后可以覆盖农田、建设用地、当前丰容度和资源数量。

## 人文组织与时间推进

### 城市与省份

- 城市由玩家动态指定的一组地块组成，可以扩张、缩小、合并或拆分。
- 省份由玩家指定的一组城市组成。
- 人口、土地、资源和经济状态归属于地块，城市边界变化不能使这些状态丢失。
- 城市和省份的数据由所属地块汇总，边界变化后必须保持一致。

### 结算周期

- 玩家操作实时生效。
- 军事系统每日结算。
- 人口与经济系统每月结算。
- 月度经济结算以地块为基础，再汇总到城市和省份。
- 全球规模的模拟采用批量处理，不要求每个地块成为独立运行的模拟对象。

## 世界数据构建原则

离线构建把现实自然地理投影到固定逻辑地块及其边、角点，生成玩法属性、水体和水道实体。各类数据源与处理规则在自然地理对应章节中说明，本节只规定共同约束。

### 空间一致性

- 数据投影须保持统一地理基准，正确处理日期变更线两侧的连续关系。
- 高程作为分类依据，不进入运行时球面几何。
- 跨主题的数据依赖须保持归属、实体与连接关系一致；尚未确定的算法不能当作已实现或已确认的规则。

### 持久身份与可重现性

- 地图资产保存地块的自然属性、水体、水道实体、有向河网、航行连接及其与地块、边、角点的关系。可推导的渲染数据和原始高分辨率源数据不作为玩法资产内容。
- 模板和源要素使用稳定键持久化；运行时临时编号不能替代持久身份。地图和存档必须保留必要的身份映射。
- 数据来源必须可追溯，记录版本、校验和、地理基准、许可和引用要求；无需自动追踪最新版本，但相同输入和规则必须能够重现构建结果。
- 数据源或派生规则变化后须重新构建；资产格式、编号或语义变化时须明确版本及兼容关系。

## 待决设计问题

各自然地理主题的数据源、参数、算法和实体结构的待完善事项记录在对应章节。本节只保留跨系统问题。

- 地块边和角点的稳定身份约定，以及逻辑拓扑采用预生成资产还是运行时生成。
- 各地图模式的颜色语义、地块选择反馈，以及边界显示随屏幕尺度变化的规则。
