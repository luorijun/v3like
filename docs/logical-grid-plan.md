# 逻辑网格方案

## 实施状态

第一版 Tile 索引纹理绘制已经实现。逻辑网格的持久化资产、完整边界数据和交互显示仍待后续实施。

地形系统已经使用等角 Cube-sphere 和四叉树 LOD 基本实现。逻辑网格不会替换或复用这套地形拓扑，两者只通过球面位置查询和显示接口发生联系。

## 已确认结论

### 拓扑

- 网格采用频率为 `358` 的固定细分二十面体，共有 `1,281,642` 个地块、`3,844,920` 条边和 `2,563,280` 个角点。
- 细分顶点作为地块中心，细分三角网作为球面 Delaunay 原始拓扑。
- 地块边界采用球面 Voronoi：三角形球面外心作为地块角点，相邻外心间的大圆弧作为边。
- 网格包含 12 个五边形，其余均为六边形；五边形不使用特殊玩法类型。
- 首版不做 Lloyd 松弛。生成时验证 Delaunay 条件、角点方向和地块有效性；验证失败时停止生成并调整中心点生成方法，不改变固定拓扑。

### 与地形系统的边界

- 逻辑网格与 Cube-sphere 地形及其四叉树 LOD 完全分离。地形拓扑和持久化资产不保存地块身份，网格不依赖地形 Face、Chunk、LOD 或顶点编号；渲染期 Chunk 可持有由两者派生的索引纹理。
- 地块身份和邻接关系在整个世界生命周期内稳定，不随地形资产参数或镜头 LOD 改变。
- 逻辑地块没有随镜头变化的语义 LOD。显示层可以按可见性和显示尺度裁剪、渐隐或隐藏边界，但不能用近似格替换真实地块语义。

### 选择与显示

- Tile 选择通过数学空间查询确定，不创建一套仅用于拾取、与地形平行的全球渲染 Mesh。
- “不创建平行 Mesh”只约束显示与拾取实现，并不预先决定逻辑拓扑是否需要离线生成、持久化或常驻内存。
- 地块显示不构建一套覆盖全球且长期存在的完整网格 Mesh，只处理当前需要显示的局部结果。
- 地块填充通过活动地形 Chunk 的索引纹理和 Shader 显示；索引纹理是可丢弃的派生渲染数据，不反向定义逻辑拓扑。

## 第一版 Tile 索引纹理绘制

### 范围

- 球面暂时没有高度，Chunk 只生成平滑单位球几何。
- 不存在独立地形纹理；地形、政治和气候等地图模式都以 Tile 为最小着色单位。
- 第一版直接显示 Tile 索引色，暂不实现自定义颜色映射和纹理接缝修复。

### TileId 编号

- 固定二十面体的 12 个顶点、20 个外侧逆时针面和 30 条边；边按 `(minVertexId, maxVertexId)` 排序并由小顶点指向大顶点。世界朝向变换不参与编号。
- 原始顶点使用 `TileId = 0..11`。
- 基础边内部点使用 `12 + edgeId * 357 + (t - 1)`，其中 `t = 1..357`。
- 基础面内部点从 `10722` 开始；每面 `63546` 个，正整数重心坐标 `(i,j,k)` 满足 `i+j+k=358`，面内按 `i`、`j` 行扫描。
- 面内序号为 `(i-1)*357 - (i-1)*i/2 + (j-1)`；三段编号共得到连续的 `0..1281641`。

### 索引色

- 索引色同时是第一版显示色，不额外分配颜色表。
- 对 `TileId + 1` 执行 21 位双射置换：依次执行 `x ^= x >> 10`、`x *= 0x0B352D`、`x ^= x >> 9`、`x *= 0x0CA68B`、`x ^= x >> 10`；每次乘法后保留低 21 位。
- 将置换结果的三组 7 位分别写入 RGB 高 7 位：`R[7:1]=x[6:0]`、`G[7:1]=x[13:7]`、`B[7:1]=x[20:14]`；低位依次复用 `x[20]`、`x[6]`、`x[13]`。
- 两个乘数均为奇数，因此与移位异或的组合在 `2^21` 空间内可逆，能严格保证当前所有 Tile 索引色唯一；编码 `0` 保留为无效值。

### UV 定位与纹理生成

- 索引纹理每个纹素使用 `((x+0.5)/256, (y+0.5)/256)` 作为 Chunk 局部 UV，再通过现有等角 Cube-sphere 映射得到单位球方向。
- 球面方向先按与 20 个基础面法线的最大点积选面，再求射线与该面的交点，转为频率 `358` 的整数重心坐标并换算 TileId。
- 平面舍入值只作为候选；最后沿 Delaunay 邻接关系向点积更大的 Tile 移动，直到当前 Tile 不劣于所有邻居，从而得到精确的球面 Voronoi 归属。
- 批量生成时，后续纹素使用左侧或上方纹素的 TileId 作为邻接修正起点，避免对每个纹素重复完整定位。

### Chunk 资源与 Shader

- Chunk 顶点使用 `VertexPositionTexture`，只保存单位球位置和 `0..1` 局部 UV；LOD 调试色改为 Chunk 级 Shader 参数。
- 每个缓存 Chunk 拥有一张 `256×256 RGBA8` 索引纹理，与 Mesh 同时创建和释放。
- 索引纹理使用 `PointClamp`，不生成 mipmap，不使用有损压缩或 sRGB 转换。
- 第一版 Shader 只变换顶点并直接输出索引纹理采样值；后续地图模式可从 RGB 高 7 位恢复 21 位置换编码，再查询颜色映射纹理。
- 一个 Chunk 预计占用约 `278 KiB`：索引纹理 `256 KiB`，`33×33` 的 `VertexPositionTexture` 约 `22 KiB`，不含驱动和对象开销。缓存数量由开发时手动调整。
